我需要调整慢sql, mysql死锁, 内存泄露的实现逻辑:
1. 代码不要出现chaos相关的字样. 避免扫代码可以指定这是chaos工程模拟的场景.
2. mysql死锁: 
    - 用户通过console页面开关该场景. 开启时, 需要选择表. 可以使用redis记录该开关状态.
    - 场景启动时, 通过请求api启动, api需要是符合正常逻辑的api, 直接锁用户选中的整张表. 如: orders, payments
    - 通过轮询确实是否需要释放锁.
    - 这样就可以灵活配置, 任何节点都可以触发死锁, 并且看起来是属于正常逻辑. 因为是别的api锁的表, 业务逻辑看不出任何破绽.
    - 后续流量正常进入即可, 这个就会自动体现到链路上: 会出现大量订单超时, 业务报错.
3. 慢sql:
    - 需要新增2张符合正常逻辑以及正常名称的表, 项目启动后需要往这2张表不断写入数据, 直到每张表的数据都>=3000万条, 其中一张表需要有一个索引,另外一张不需要索引.
    - 用户通过console页面开关该场景.  可以使用redis记录该开关状态. 以及join哪张表.
    - 业务的每个节点都需要访问redis, 根据key判断本次是否要join该表, 并且需要根据该大表的字段进行过滤. 如果是有索引的表, 则需要破坏索引, 不让走有索引.
    - 这样就可以灵活配置, 任何节点都可以触发慢sql, 并且看起来是属于正常逻辑. 因为这是join表行为. 优化空间就是`优化sql让sql走索引` 或 `增加索引`.
4. 内存泄漏:
    - 跟前面差不多的逻辑. 也是通过redis进行开关.
