## 1. 产品定义

为 `traffic-control-plane` 增加双语运营界面，使培训运营人员可以在 English 和简体中文之间切换，在不同语言环境下完成故障演练、流量 Runner、数据操作和告警管理。

该能力只服务于受 Operator 权限保护的运营控制台，不改变消费者商城、业务服务或 Gateway 的业务接口。语言是控制台的展示偏好，不是用户身份、权限或业务数据的一部分。

## 2. 目标与非目标

### 2.1 目标

1. 覆盖控制台全部运营页面，而不是只翻译导航或首页。
2. 提供 English 与简体中文两种完整的静态界面文案。
3. 允许运营人员在登录前选择语言，登录后继续使用同一语言。
4. 记住运营人员主动选择的语言，刷新页面或重新打开控制台后保持选择。
5. 使标题、按钮、字段、状态展示、确认弹窗、空状态、加载状态、Toast、Tooltip 和无障碍文本保持一致。
6. 根据当前语言展示日期、时间、数字和容量，但不改变业务时间语义或机器可读值。
7. 对场景、运行记录和告警数据保留稳定的标识与协议值，避免翻译影响操作安全和排障。

### 2.2 非目标

- 不为 Shopfront 或其他业务服务增加翻译能力。
- 不引入 `/en`、`/zh-CN` 等语言前缀路由。
- 不改变当前页面路径、登录跳转、`returnTo` 参数或 API 路径。
- 不修改 Operator 鉴权、CSRF、内部服务认证和 `src/middleware.ts` 的行为。
- 不翻译或改写后端/Route Handler 返回的原始错误消息。
- 不翻译场景码、状态码、服务名、操作名、ID、表名、cron 表达式、PromQL、YAML 或 API 字段名。
- 不自动翻译运营人员编辑并保存到 Prometheus/Alertmanager 的规则内容。
- 不在本次需求中增加浏览器语言协商、语言级权限或用户账号级语言配置。

## 3. 用户与使用场景

| 用户 | 目标 | 典型操作 |
| --- | --- | --- |
| 中文培训运营人员 | 使用中文完成演练操作 | 登录、创建/停止 Fault Run、查看恢复证据、配置 Runner |
| English 培训运营人员 | 使用英文完成相同操作 | 查看场景、检查活动、编辑告警、确认恢复结果 |
| SRE/测试人员 | 在两种语言下复核同一运行结果 | 对比状态、时间、指标和原始错误信息 |

## 4. 语言策略

### 4.1 支持语言

| 显示语言 | locale | 说明 |
| --- | --- | --- |
| English | `en` | 首次访问默认语言 |
| 简体中文 | `zh-CN` | 通过语言选择器主动切换 |

首次访问或语言偏好无效时固定使用 English，不根据浏览器 `Accept-Language` 自动切换。这样可以保持现有控制台的默认体验，并避免服务端与浏览器初始语言不一致。

### 4.2 语言切换

1. 登录页提供语言选择器，未登录运营人员可以先选择语言。
2. 已认证页面的共享头部继续提供同一个选择器。
3. 切换后当前路径和查询参数保持不变，页面文案更新为目标语言。
4. 选择结果写入独立的 `control_plane_locale` 偏好 Cookie。
5. 语言偏好不影响 `operator_session`、`operator_csrf` 或任何业务请求认证信息。
6. Cookie 缺失、过期或包含未知值时回退 English。

### 4.3 语言一致性

以下内容必须跟随当前语言：

- 页面标题、导航和页脚。
- 操作按钮、确认按钮、取消按钮和等待状态。
- 场景标签、场景分组、场景描述和已知状态的显示名称。
- Fault Run 历史、详情、恢复、清理和读请求汇总中的界面说明。
- Runner 配置、活动、账号摘要、数据预热和补齐控制的界面说明。
- Alerts 的编辑、路由、接收器和模态框 UI 说明。
- 日期选择器的月份、星期、导航标签和日期格式。
- `title`、`aria-label`、隐藏文本以及其他无障碍提示。

以下内容保持原值：

- 后端消息、错误详情、稳定错误码和未知状态值。
- `faultRunId`、`traceId`、订单号、客户 ID、服务名和操作名。
- 运营人员编辑的 PromQL、YAML、规则摘要、规则描述和 receiver 值。
- API 请求字段、数据库表名、cron 表达式和机器日期值。

## 5. 页面覆盖范围

| 路由/区域 | 本次覆盖内容 | 不改变的内容 |
| --- | --- | --- |
| `/login` | 产品标题、登录说明、用户名/密码标签、提交/加载状态、语言选择、前端错误回退、无障碍文本 | 登录 API、认证错误原文、`returnTo` 逻辑 |
| `/` | 场景导航、分组、卡片、参数、运行状态、历史、详情、恢复/清理、确认框、Toast 和 Fault Run 摘要 | 场景码、目标服务/操作、运行 ID、API 值和后端消息 |
| `/runner` | 生命周期配置、Runner 状态、指标、账号摘要、活动、补券/库存补齐和数据控制 | 配置字段语义、比例数值、cron、活动 ID、客户 ID 和服务端错误 |
| `/operations` | 数据预热、补齐、任务状态、操作结果、确认框和反馈 | 表名、任务 ID、参数值、API 结果和后端消息 |
| `/alerts` | 规则、路由、接收器、编辑器、模态框、按钮、帮助说明和空/加载状态 | PromQL、YAML、规则内容、receiver 值、severity/source 值和解析错误原文 |
| 共享壳层 | 导航、主题切换、登出、页脚、语言入口和所有公共可访问性文本 | 认证行为、页面路径和主题状态 |

## 6. 功能需求

### FR-1 语言选择

系统必须提供可键盘操作、带可见当前值和可访问名称的语言选择器。选择器至少包含 `English` 和 `简体中文` 两项。

### FR-2 默认语言

不存在有效 `control_plane_locale` 时，所有页面必须使用 English。首次渲染的 `<html lang>` 必须为 `en`。

### FR-3 语言持久化

选择语言后，刷新当前页面、重新进入同一控制台或重新登录，都应恢复上次选择。偏好 Cookie 应覆盖整个控制台路径，但不能携带认证或业务身份。

### FR-4 全页面覆盖

登录、场景、Runner、Operations、Alerts 和共享壳层的前端自有文案必须均有两种语言。不能出现导航已翻译而弹窗、日期选择器或无障碍标签仍固定为 English 的主要流程。

### FR-5 稳定数据保护

切换语言不能改变请求 URL、请求体、场景标识、状态值、服务名、操作名、数据库字段、PromQL、YAML 或 Alertmanager 配置内容。

### FR-6 动态消息边界

后端返回的 `message`、错误详情、告警解析错误和任务错误信息保持原文展示。前端自有的加载、确认、空状态和 fallback 文案必须随语言切换。

### FR-7 日期和数字展示

日期、时间、数字和容量单位应根据当前语言进行展示；业务日期仍使用 `Asia/Shanghai` 语义，机器输入值仍保持 `YYYY-MM-DD`、ISO、cron 等稳定格式。

### FR-8 无障碍与响应式

语言切换器、导航、按钮、日期选择器、模态框和图标按钮必须在两种语言下有正确的 `aria-label` 或可见名称。桌面和窄屏布局不得因中文文本扩展发生遮挡、裁切或功能控件不可操作。

### FR-9 错误回退

消息键缺失或未知场景/状态值不能导致页面崩溃。未知稳定标识应回退到原始值；语言 Cookie 非法时回退到 English。

### FR-10 鉴权隔离

语言切换和语言 Cookie 不得绕过、削弱或改变登录、Operator 权限、CSRF 和 `/internal/**` 访问控制。

## 7. 体验与安全要求

### 7.1 交互体验

- 语言选择器在登录页和认证后的共享头部均可见。
- 切换语言后保持当前页面，避免把运营人员带回首页或登录页。
- 切换不应明显先显示另一种语言再替换；服务端输出的语言和客户端消息必须一致。
- 长文本应在卡片、按钮、弹窗和日期选择器中自然换行，不得通过隐藏文本解决布局问题。
- 场景状态的显示名称可以翻译，但原始状态值在需要排障的详情位置仍可被识别。

### 7.2 安全与隐私

- `control_plane_locale` 只保存 `en` 或 `zh-CN`，不保存用户名、客户 ID、token 或其他敏感数据。
- 语言 Cookie 与 `operator_session`、`operator_csrf` 分开管理。
- 翻译目录不得包含密码、access token、session token、authorization header 或业务客户数据。
- 翻译只能改变展示文本，不能成为服务端鉴权或业务规则的输入。

## 8. 验收标准

1. 清除语言偏好后访问 `/login`，页面为 English，且 `<html lang="en">`。
2. 未登录时在 `/login` 选择简体中文，当前页面不跳转，刷新后仍为中文，且 `<html lang="zh-CN">`。
3. 登录后访问 `/`、`/runner`、`/operations` 和 `/alerts`，所有主要标题、操作、弹窗、反馈和无障碍文本均能切换。
4. 场景卡片、Fault Run 历史/详情、Runner 活动、日期选择器和 Alerts 编辑器在两种语言下均能正常渲染。
5. 已知场景、分组和状态有对应的中英文显示名；未知场景或状态仍显示原始标识，不抛出渲染异常。
6. 后端返回的原始错误、动态任务错误和告警解析错误仍保持原文，不被错误地当作翻译键或截断。
7. 日期和数字随语言变化，但上海时区、ISO 日期、cron、ID、服务名、表名和状态码保持不变。
8. 语言切换不修改 pathname、query、`returnTo`、认证 Cookie、业务请求 payload、PromQL、YAML 或规则持久化内容。
9. 未认证访问受保护页面和 `/internal/**` 的既有鉴权行为与国际化改造前一致。
10. 在桌面和窄屏宽度下，语言选择器不遮挡品牌、导航、主题和登出按钮，中文长文本不溢出主要容器。
11. `test:i18n`、`test:runner`、`typecheck`、`lint` 和 `build` 均通过。

## 9. 成功指标与发布策略

### 9.1 成功指标

- 两种语言的所有主要运营流程均可独立完成，不需要切回 English 才能操作。
- 语言切换不产生新的鉴权失败、错误路由或业务请求差异。
- 消息目录不存在键不一致、占位符丢失或未知状态导致的页面崩溃。
- 运营人员在 Fault Run、Runner、Operations 和 Alerts 页面看到的时间和数字仍具备一致的业务语义。

### 9.2 发布策略

首版作为控制台前端变更随现有部署发布，不需要数据库迁移、业务服务发布或 API 版本升级。实现使用 `next-intl`，具体依赖版本在技术设计规定的兼容性检查后锁定。发布前必须完成类型检查、构建和两种语言的页面走查。
